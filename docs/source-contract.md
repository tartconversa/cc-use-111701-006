# 来源契约

授权伙伴发送 X12 004010 的 ISA/GS/ST 852；ISA 定义元素、组件和段分隔符，IEA/GE/SE 控制号与数量须核对。业务 SKU 位于 LIN，数量位于 QTY；伙伴身份由传输配置给出，不用控制号代替。接收结果按交易集保留接受或拒绝原因，并可生成对应的功能确认原文。

## 分隔符与信封边界

* 分隔符不假定固定字符：元素分隔符取 ISA 第 4 个字符，组件分隔符取 ISA 第 105 个字符，段终止符取第 106 个字符；三者必须互不相同，ISA16 必须等于组件分隔符。
* ISA 段固定 106 字符（含终止符），ISA01–ISA16 逐字段宽度校验，ISA12 必须为 `00401`。
* 解析按交换（ISA/IEA）、功能组（GS/GE）、交易集（ST/SE）三层保留控制号边界，并核对 IEA/GE/SE 的回指控制号与声明数量。
* 错误分三层：交换级（如 IEA 控制号不符）影响整份交换；组级（如 GE 计数不符）只拒该组；交易集级（如 SE 计数不符、QTY 非数字）只拒该单据，同组兄弟单据照常接受。

## 852 业务内容

* SKU 取自 LIN 中成对的“限定符/标识”，优先顺序 `SK, UP, UA, EN, BP, IT`（有 SK 用 SK）。
* 数量取自 QTY：QTY01 限定符（`19` 在手、`31` 售出、`33` 可用等，未知限定符原样保留）、QTY02 数值（按字符串/Decimal 处理，拒绝负数与非数字）、QTY03 计量单位。
* 业务地点取自 N1（优先 N104 代码，其次 N102 名称）；N1 开启新的报告位置循环，其后游离的 QTY 拒绝。
* 每条数量都带字节级来源位置（段标签、起止偏移、元素下标），可直接回指原件。
* 一个交易集没有任何有效数量条目时以 `NO_ACTIVITY` 拒绝，不把空集解释成完整采集。

## 修订单与版本关系

* 头部 `REF*CR` 的值形如 `ISA控制号/GS控制号/ST控制号`，指向被修订的原交易集。
* 原单必须已被接受，否则修订单分别以 `ORIGINAL_NOT_FOUND` / `ORIGINAL_WAS_REJECTED` / `CORRECTION_REF_MALFORMED` 拒绝。
* 修订单与原单形成版本链；当前数量视图只取链头（整单替换），绝不把两个版本的数量相加，链上历史版本仍可经 `Store.lineage` 追溯。

## 幂等、冲突与恢复

* 台账按伙伴隔离（控制号在不同伙伴间可以重用）。同一伙伴内：
  * 同 ISA 控制号且 SHA-256 相同 → 重投回放首次收据（`replay=true`），事件日志不新增，997 逐字节一致。
  * 同 ISA 控制号但 SHA-256 不同 → 以 `DUPLICATE_CONTROL_DIFFERENT_BYTES` 冲突拒收并留痕，绝不覆盖既有结论。
* 原件按 SHA-256 内容寻址落盘；事件写仅追加 JSONL，文件锁 + fsync + 原子改名保证进程重启后重放结论一致；日志行损坏时拒绝在不确定状态下继续。
* ISA 都无法识别的传输以 `INTERCHANGE_UNPARSEABLE` 留痕并返回可核对收据（含原始字节 SHA-256），同字节重投结论一致。

## 997 功能确认

* 每个入站功能组生成一份 997（`GS*FA`），沿用入站 ISA 声明的分隔符。
* AK2/AK5 逐交易集给出 `A`（接受）或 `R`（拒绝，带标准错误码与 AK3 段定位）；AK9 汇总 `A`/`R`/`P`（部分接受）。
* 997 的 ISA/GS 控制号由原件哈希与组控制号确定性派生，同一字节内容重投产生相同确认。
* 生成的 997 可被同一解析器回读，SE/GE/IEA 计数自洽。

已有单响应输入为 fixtures/sample.json，含 source_id、url、status、headers 和 body_base64；原件摘要由 source.Response.sha256 给出。旧 JSON 流程（`app.service.inspect`）保持不变，X12 接收经 `app.edi.receive_raw` 与 `app.store.Store` 走独立路径。
